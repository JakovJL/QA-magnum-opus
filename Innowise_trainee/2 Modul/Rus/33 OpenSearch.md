## Что такое OpenSearch

**OpenSearch** — поисковая система и хранилище данных, оптимизированное для быстрого поиска, фильтрации и аналитики.

**Цель:** быстро находить документы по тексту и полям, когда обычная база данных не подходит для сложного поиска.

OpenSearch часто используют для поиска товаров, логов, событий и аналитических данных.

---

## Индекс и документ

- **Index** — набор документов одного типа; похож на таблицу по назначению, но устроен иначе;
- **Document** — единица данных в формате JSON;
- **Mapping** — описание полей и их типов;
- **Shard** — часть индекса, которая помогает распределять данные;
- **Replica** — копия shard для отказоустойчивости и чтения.

```json
{
  "id": 42,
  "name": "Wireless mouse",
  "category": "accessories",
  "price": 25.50
}
```

## Полнотекстовый поиск

При полнотекстовом поиске строка разбирается на части — токены. Поэтому поиск по полю `text` может находить разные формы слова, в зависимости от настроенного анализатора.

Для точной фильтрации обычно используют поле типа `keyword`, а для поиска по тексту — поле типа `text`.

> [!tip] `text` и `keyword`
>
> | Тип поля | Для чего подходит |
> |---|---|
> | `text` | Поиск по словам в названии или описании |
> | `keyword` | Точное значение, фильтр, сортировка, агрегация |

## Индексация данных

Данные могут попадать в OpenSearch напрямую через API или асинхронно из основной базы данных через очередь и отдельный сервис индексации.

Во втором случае возникает задержка: запись уже есть в основной системе, но ещё не появилась в поиске. Это называется eventual consistency — согласованность достигается не мгновенно.

Тест должен учитывать это требование: ожидать появление документа ограниченное время, а не делать одну мгновенную проверку.

---

## Что проверять тестировщику

- появился ли в индексе новый или обновлённый документ;
- правильно ли перенесены поля и их типы;
- находится ли документ по нужному запросу;
- не находится ли по запросу, который не должен подходить;
- корректны ли фильтры, сортировка и пагинация;
- исчезает ли документ из поиска после удаления или скрытия;
- соответствует ли задержка индексации требованиям.

---

## Типичные ошибки

| Ошибка | Как сделать лучше |
|---|---|
| Проверять поиск сразу после записи | Ждать появления документа в пределах согласованного тайм-аута |
| Ожидать точный поиск от поля `text` | Для точного сравнения использовать `keyword` |
| Проверять только число результатов | Проверять также содержимое и порядок результатов |
| Считать индекс основной базой данных | Сверять источник данных и поисковый индекс отдельно |

## Вопросы на собеседовании

### Вопросы начального уровня

**1. Что такое OpenSearch?**

OpenSearch — поисковая система и хранилище данных, оптимизированное для быстрого поиска, фильтрации и аналитики.

**2. Какие основные компоненты OpenSearch?**

Index (набор документов), Document (единица данных в JSON), Mapping (описание полей), Shard (часть индекса), Replica (копия shard).

**3. В чём разница между полями text и keyword?**

text — для поиска по словам (разбивается на токены), keyword — для точного значения, фильтра и сортировки.

**4. Что такое eventual consistency в контексте OpenSearch?**

Задержка между записью в основную систему и появлением данных в поисковом индексе.

### Вопросы среднего уровня

**1. Почему нельзя проверять поиск сразу после записи данных?**

Из-за eventual consistency данные могут появиться в индексе не мгновенно. Нужно ждать в пределах согласованного тайм-аута.

**2. Что такое mapping в OpenSearch?**

Описание полей документа и их типов. Определяет, как данные хранятся и индексируются.

**3. Что должен проверять тестировщик при работе с OpenSearch?**

Появился ли документ в индексе; правильно ли перенесены поля и типы; находится ли документ по нужному запросу; не находится ли по неподходящему запросу; корректны ли фильтры, сортировка и пагинация.

### Вопросы повышенного уровня

**1. Чем отличается проверка только количества результатов от проверки содержимого?**

Проверка только количества может пропустить ошибку: вернулось правильное число документов, но не те документы. Нужно проверять содержимое и порядок результатов.

**2. Почему OpenSearch не следует считать основной базой данных?**

OpenSearch оптимизирован для поиска, а не для транзакционной надёжности. Данные могут потеряться при сбое, если не настроены реплики. Источник данных и поисковый индекс нужно сверять отдельно.

**3. Когда поле text не подходит для поиска?**

Когда нужно точное совпадение. text разбивает строку на токены, поэтому поиск по полному значению может не найти документ. Для точного сравнения используется keyword.

### Вопросы с кодом

**1. Что описывает этот mapping?**

```json
{
  "id": 42,
  "name": "Wireless mouse",
  "category": "accessories",
  "price": 25.50
}
```

**Ответ:** Это пример документа OpenSearch: id — числовой идентификатор, name — название товара, category — категория, price — цена.

**2. Какая ошибка допущена в тесте, если он проверяет только это?**

```java
assertThat(searchResults.getTotalHits(), equalTo(3));
```

**Ответ:** Проверяется только количество результатов, но не их содержимое и порядок. Тест проходит, даже если вернулись не те документы.
